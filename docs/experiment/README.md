## Сбой инфраструктуры и восстановление

Первый вызов Qwen3 дважды завершился HTTP 500: `llama runner process has terminated: signal: killed`. По журналу runner не смог инициализировать CUDA, выгрузил на GPU 0/49 слоёв и пытался разместить модель на CPU. На хосте RTX 3090 работала, внутри контейнера `nvidia-smi` возвращала `Failed to initialize NVML: Unknown Error`.

После разрешённого перезапуска только контейнера `ollama` GPU стала доступна. Журнал загрузки Qwen3: 49/49 слоёв на GPU; `ollama ps`: 100% GPU, контекст 32768. Причина потери доступа контейнера к GPU не установлена. Конфигурация контейнера и Modelfile не менялись.

Приложение перезапущено, сохранённая упавшая задача повторена через `POST /api/v1/failures/2/retry`. Экземпляр остался прежним: `01a1b205-7cf9-7765-b2ae-7f4659e87760`. Так проверено сохранение состояния между запусками приложения и ручное восстановление после технического сбоя.

## Реальный прогон

Задание: функция Go `UniqueSorted`, сортировка уникальных целых чисел без изменения входа, ненулевой пустой срез для nil/empty, табличные тесты для крайних случаев.

- Итерация 1: исполнитель предложил код с ошибочным вызовом `copy`. Рецензент отклонил решение и вернул замечания.
- Итерация 2: исполнитель изменил порядок аргументов и вывод результатов тестов. Рецензент ответил `approved: true`.
- BPMN завершён, `round: 2`, `outcome: accepted`.

**Независимая проверка выявила ложное одобрение.** В принятом коде переменная `copy` перекрывает встроенную функцию. Компиляция извлечённого Go-блока в отдельном временном модуле завершилась ошибкой:

```text
# outputcheck
./main.go:17:5: invalid operation: cannot call copy (variable of type []int): []int is not a function
```

Проверялась именно компиляция (`go build ./...`), программа не запускалась. Дополнительно в ответе отсутствует явная проверка неизменности входного среза, хотя рецензент утверждает обратное. Ошибка не была исправлена вручную в сохранённом ответе. `accepted` означает согласие LLM-рецензента, а не прохождение компилятора или тестов. Для следующего этапа нужен отдельный инструментальный гейт в изолированной среде.

Артефакты: [полная история](real-run.json), [принятый Go-блок](approved-output.go.txt). История содержит промежуточные ответы и финальные переменные.

## Проверки приложения

Прошли:

- генерация нового BPMN и сборка приложения;
- `go vet ./...`;
- `GO_BPM_TEST_DSN=... go test -race -p 1 ./...` с PostgreSQL;
- три сценария нового процесса: принятие сразу, отрицательное ревью с передачей замечаний и последующим принятием, остановка по лимиту;
- проверки адаптера: выбор роли/модели, JSON Schema, наследование параметров, неверный JSON, отсутствие вердикта, обрезанный ответ, HTTP-ошибка.

Эти тесты проверяют приложение и управление процессом. Они не доказывают корректность ответов живых моделей. Docker-образ и запуск через Compose в этом окружении не проверялись: локальный пользователь не имеет доступа к Docker daemon. CI проверяет PostgreSQL, генерацию, сборку, vet и тесты без обращения к Ollama.
